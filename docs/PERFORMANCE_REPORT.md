# Headed Chromium Performance Profiling Report: KAI Student OS

**Дата и время профилирования:** 18 сентября 2026 г., 00:46 (MSK)  
**Инструменты профилирования:** Playwright (Headed Chromium, аппаратное GPU-ускорение включено), Chrome DevTools Protocol (`Performance.getMetrics`), `PerformanceObserver` (Long Tasks API, Navigation Timing API, User Timing API).  
**Тестовый хост:** Windows 11, FastAPI Uvicorn на `http://127.0.0.1:8899`, группа 5108 (450 реальных задач, 13 курсов).

## 1. Executive Summary: Before vs After Optimizations

В ходе первичного аудита в **HEADED Chromium** была выявлена главная проблема производительности: **разрастание дерева DOM до 11 521 узла** при одновременном рендеринге 450 задач во вкладке «Задания» без изоляции стилей и макета. Это приводило к синхронной перерисовке всего дерева при скролле (65% кадров дропались ниже 60 FPS) и блокировке основного потока на 260.5 мс при смене темы.

После точечных оптимизаций (`content-visibility: auto`, `contain: layout style`, делегирование событий вместо 450 слушателей) производительность кардинально улучшилась:

|---|---|---|---|

## 4. Обнаруженные и устраненные узкие места (Bottlenecks)

1. **Large DOM Subtree Overhead (11 521 узел) [УСТРАНЕНО]:**
   - *Проблема:* Все 450 строк задач рендерились плоским списком, создавая огромную нагрузку на Style Recalculation.
   - *Решение:* На элементы `.course-accordion-card` и `.task-row` добавлены правила `content-visibility: auto`, `contain-intrinsic-size: 0 160px` и `contain: layout style`.

2. **Excessive Event Handlers (450 слушателей на клик) [УСТРАНЕНО]:**
   - *Проблема:* На каждый вызов `renderTasksMainView()` браузер находил 450 чекбоксов через `querySelectorAll` и вешал 450 замыканий.
   - *Решение:* Заменено на один постоянный делегированный слушатель на `#tasks-main-container`.

3. **Theme Switch Stutter (260 ms Lockup) [УСТРАНЕНО]:**
   - *Проблема:* Смена темы замораживала основной поток на четверть секунды из-за инвалидации стилей всего дерева.
   - *Решение:* Благодаря `content-visibility: auto` время переключения снизилось до **18.5 ms**.

4. **Backdrop-filter & Composite Layering [ВЕРИФИЦИРОВАНО]:**
   - *Проверка:* Убедились, что `backdrop-filter` активен только на 5 плавающих слоях (Dock, Top Bar, Modal Sheets, Composer, Toast). Ни одна карточка в списке задач не использует `backdrop-filter: blur`, что гарантирует отсутствие избыточных слоев растеризации GPU.
